# AP-FP-007 — Publication Style Guide

## Document Control

- Publication: AgriPartners Development Round Funding Package
- Edition: Authoritative Master Edition
- Version: v1.0 R1
- Scope: publication presentation and editorial consistency only
- Authority: subordinate to the approved Sections, Appendices, and document-control instruments

## 1. Governing Principle

This guide standardizes presentation without changing approved substantive meaning. If a style rule could alter meaning, an approved term, a budget value, a Milestone, governance, funding strategy, or Acceptance Criteria, the approved source controls and the style rule must not be applied.

## 2. Terminology

- Use defined terms exactly as established in the authoritative Sections and Appendix A.
- Preserve capitalization for defined terms, including Milestone, Exit Criterion/Exit Criteria, Acceptance Criteria, and named work products.
- Do not introduce synonyms for a defined term where the synonym could create a second interpretation.
- Use “Section” and “Appendix” with initial capitals when referring to a numbered or lettered document component.
- A derived matrix or summary must not redefine its authoritative source.

## 3. Heading Hierarchy

- Use one level-one heading for each standalone file title.
- Use level-two headings for principal numbered divisions and level-three headings for subdivisions.
- Do not skip heading levels for visual effect.
- Keep heading wording aligned with the authoritative title and table of contents.
- Apply page breaks and keep-with-next formatting as publication controls only; they must not alter numbering or text.

## 4. Numbering

- Number Sections 1–21 and Appendices A–J using their approved identifiers.
- Preserve approved internal clause, table, figure, Milestone, and Acceptance Criteria numbering.
- Use Arabic numerals for numbered Sections and uppercase Latin letters for Appendices.
- Do not renumber an approved item solely to improve page layout.

## 5. Capitalization

- Use title case for formal document and component titles when the approved title uses it.
- Use sentence case for ordinary prose headings unless the authoritative source establishes another form.
- Preserve approved capitalization of organizations, roles, systems, defined terms, and Milestone titles.
- Do not normalize capitalization inside quoted material or identifiers.

## 6. Document References

- Refer to a numbered component as “Section N” and to a lettered component as “Appendix X.”
- Include a clause or heading title when needed to disambiguate a reference.
- Use the exact controlled filename or document identifier for repository links.
- Relative Markdown links are preferred within the documentation repository.
- References must resolve to an existing controlled document; descriptive text must not imply that a derived document supersedes its source.

## 7. Citation Rules

- Cite external material only where the approved content requires it.
- Preserve the approved citation text, source attribution, date, and locator.
- Use stable hyperlinks where available and record an access date when the source is time-sensitive.
- Do not add an external source as authority for an approved internal rule without formal content approval.
- Tables or summaries derived from another package component must cite that authoritative Section or Appendix directly.

## 8. Appendix References

- Cite appendices by letter and exact approved title on first substantive reference.
- Later references may use the appendix letter when unambiguous.
- An Appendix that derives a matrix, checklist, or summary from a Section must identify the controlling Section.
- If an Appendix conflicts with an authoritative Section, the Section controls and the Appendix requires controlled correction.

## 9. Monetary Notation

- Preserve the currency and amount exactly enough to prevent ambiguity.
- Use comma thousands separators and a period for decimals when decimals are required.
- State another currency explicitly when it is not United States dollars.
- `USD 40,000` and `$40,000` are approved equivalent monetary representations. Both may remain in approved content unless a future publication style explicitly standardizes one notation.
- A notation-only difference must not be treated as a budget inconsistency when the currency and numeric value are identical.

## 10. Publication Application

This guide resolves publication-style consistency questions prospectively. It does not authorize retroactive edits to frozen approved content. Any future substantive standardization requires the applicable change-control approval.
